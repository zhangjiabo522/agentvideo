## 1. 产品定义

### 1.1 一句话定位

一个让 AI Agent 通过工具制作视频、供人实时观察的工作台：用户描述目标，AI 经由 MCP 或内置多轮工具调用读取工程、编排分镜、编辑场景、移动裁剪片段、调度生图与旁白、预览和导出。人通过同步画布、时间线和步骤记录查看过程、提出修改要求，需要时人工接管。

核心交付物同时包含可继续编辑的工程和最终视频。工程保留文字、图片、图形、图表、图层、时间、动画、音频以及生成记录，视频文件用于播放和发布。

### 1.2 核心原则

1. **AI 是工具操作者。** 核心能力是文本理解、任务规划与标准工具调用，AI 逐步完成实际制作；仅输出方案或完整工程 JSON 不算执行成功，视频生成接口不是主流程依赖。
2. **画面由程序渲染。** 文字排版、图形、图表、图片运动和转场通过确定的渲染逻辑实现。
3. **工程持续可编辑。** 生成后能改内容、改布局、改时间，也能撤销、保存和再次打开。
4. **AI 与人工接管共用项目数据。** 工具每步保存并广播有效修改；人工接管产生的新位置、时间和约束会成为 AI 后续操作的依据。
5. **修改有明确范围。** 修改一句字幕或一个镜头时，系统应保留其余内容。
6. **生图可接入、可替换、可跳过。** 没有生图服务也可以完成一个视频。
7. **失败可以恢复。** 一个素材或镜头失败，不应使整份工程丢失。
8. **可视化是人的观察面。** 默认实时观看，不要求人通过拖拽完成 AI 任务；人工操作作为接管能力保留。
9. **接入方式开放。** 外部 AI 可通过本机 HTTP MCP 操作，内置 AI 与外部 AI 共用同一工具目录、工程校验和版本规则。

### 1.3 能力边界

| 视频类型 | 首版适配程度 | 实现方式 |
| --- | --- | --- |
| 产品介绍、功能说明 | 高 | 截图、文字、局部高亮、镜头移动、图形动画 |
| 知识讲解、课程片段 | 高 | 分步文字、示意图、结构图、图表、字幕 |
| 数据报告、信息图视频 | 高 | 数据驱动图表、数字变化、标注和动画 |
| 图片故事、活动宣传 | 高 | 图片、排版、平移、缩放、转场和音乐 |
| 品牌动画、动态海报 | 中高 | 字体、颜色、标志和预设动画组合 |
| 应用操作演示 | 中 | 首版使用上传截图添加说明和编排；录屏输入后续支持 |
| 复杂三维动画 | 低，后续研究 | 需要专门的三维场景与组件体系 |
| 写实人物表演、连续物理动作、电影镜头 | 不作为首版承诺 | 文本代码与静态生图无法稳定提供这些能力 |

生图输出是静态图片。对图片做平移、缩放、裁剪或分层运动，并不等同于生成真实人物动作。

## 2. 用户与需求

### 2.1 首批目标用户

优先服务需要稳定产出信息类短视频的个人创作者和小型团队，而不是先覆盖全部专业剪辑场景。

| 用户 | 典型任务 | 主要痛点 | 需要得到的结果 |
| --- | --- | --- | --- |
| 产品运营、小团队市场人员 | 制作功能介绍、活动通知、产品更新视频 | 重复排版，修改沟通成本高 | 可以快速修改文案、截图和品牌样式的短视频 |
| 教师、知识创作者 | 把知识点、文章、讲义变成视频 | 不会动画制作，信息难以视觉化 | 内容准确、结构清晰、可调整讲解节奏的视频 |
| 开发者、技术作者 | 展示软件、流程、架构和数据 | 普通剪辑器难以表达程序化内容 | 可以复用组件、修改数据和动画参数的工程 |
| 设计与内容协作者 | 调整 AI 生成初稿 | 生成结果难以局部修改 | 可选中、可编辑、可回退的对象和时间线 |

### 2.2 主要需求

- 我希望向 AI 描述成片目标和素材，它能实际调用工具完成制作和导出。
- 我希望实时看到 AI 改了哪个镜头、用了什么素材，以及当前画面和时间线。
- 我希望自己的 AI 客户端能通过 MCP 接入，而不必让 AI 模拟鼠标点击。
- 我希望需要精修时接管标题或片段，再让 AI 读取新工程继续制作。
- 我希望说“第二个镜头慢一点”，系统只修改相关镜头和必要的后续时间。
- 我希望自己拖动过的布局，在后续 AI 修改中继续保留。
- 我希望更换生图服务或使用上传图片，不影响已有工程。
- 我希望修改视频中的数字后，图表和相关标注同步更新。
- 我希望关闭页面后，再次打开仍能接着编辑。
- 我希望预览中看到的文字、动画和时序，与导出视频一致。

### 2.3 典型示例

用户输入：“做一个 45 秒竖屏视频，介绍一款记账软件。面向刚工作的年轻人，突出自动分类、月度统计、预算提醒。使用我上传的三张截图，风格简洁，结尾放下载提示。”

AI 读取工程，规划约 5 个镜头，通过工具添加截图、标题、重点标记和图表，安排时间、调用可选旁白并导出。人实时观看并说“第三个镜头使用真实数据”“结尾改成下载提示”，AI 提交局部修改；需要精修时人可以接管，再交回 AI 继续。

这个示例必须在没有生图模型、语音模型和视频生成模型的情况下完成。

## 3. 产品目标与成功指标

### 3.1 首版产品目标

让用户通过“描述目标 → AI 读工程并规划 → AI 逐步调用剪辑与素材工具 → 人实时观看并反馈 → AI 保存和导出”完成视频。人工接管为可选能力，基础视频无需人写代码或手动排列每个片段。

首版优先证明三个问题：AI 能否实际完成工具操作和成片；人能否看清过程并可靠地停止或接管；工程能否持续保存、修正和稳定导出。

### 3.2 核心指标

| 指标 | 统计口径 | 首版建议目标 |
| --- | --- | --- |
| 首次任务成功率 | 首次任务在 24 小时内生成有效工程并成功导出的用户数 / 发起首次生成的用户数 | 内测阶段达到 70%，随后依据真实数据调整 |
| 完整初稿生成成功率 | 形成所有镜头且通过工程校验的任务数 / 发起生成的任务数 | 固定验收集达到 90% |
| 局部修改范围准确率 | 修改范围与用户指令一致且未误改其他内容的次数 / 局部修改次数 | 固定验收集达到 95% |
| 手动编辑保留率 | 未被授权改动的手动属性仍保持正确的次数 / 被检查次数 | 固定验收集要求 100% |
| 渲染成功率 | 合法工程成功得到可播放视频的次数 / 合法工程渲染次数 | 固定验收集达到 98% |
| 初稿等待时间 | 从提交需求到完整可播放预览的时长 | 记录中位数和 95 分位数，原型后定目标 |
| 人工修改耗时 | 初稿出现到用户开始首次导出的有效编辑时间 | 与相同任务的人工制作基线比较 |
| 实际制作成本 | 模型、生图、存储和渲染成本 / 成功导出的视频分钟数 | 原型和内测持续记录 |
| 编辑可信度 | 用户是否认为 AI 修改可控、可撤销、不会破坏已完成内容 | 内测访谈与任务观察 |

这些数值是规划目标，不是已经达成的指标。成功率必须展示样本量和失败类型；用户主动取消与供应商服务失败单独记录，不能直接消失在报表中。

## 4. 首版范围

### 4.1 视频规格

| 项目 | 首版规格 |
| --- | --- |
| 视频时长 | 15 至 120 秒 |
| 项目比例 | 16:9、9:16、1:1 |
| 帧率 | 30 帧/秒，项目创建后固定 |
| 导出分辨率 | 与比例对应的 1080 级别，支持降低到 720 级别 |
| 视频格式 | MP4，H.264 视频与 AAC 音频 |
| 镜头数量 | 最多 20 个 |
| 标准视觉对象 | 每个工程最多 300 个，不含音频与字幕条目 |
| 交互设备 | 首先支持桌面浏览器与鼠标键盘 |
| 移动端 | 可查看工程状态和预览；完整编辑延后 |

工程采用固定画布尺寸。预览缩放只影响显示大小，不改变项目坐标。已有工程允许切换比例，但需要重新排版的镜头必须先展示影响，不能直接裁掉内容。

### 4.2 优先级定义

- **P0：** 首次发布必须具备，缺失会阻断完整制作流程。
- **P1：** 提升制作效率与质量，在核心流程稳定后实现。
- **P2：** 复杂扩展，后续依据真实使用需求决定。

| 模块 | P0 | P1 / P2 |
| --- | --- | --- |
| 需求输入 | 文字、图片上传、目标时长、比例与风格选择 | 文档与演示文稿解析、网址内容导入 |
| 脚本与分镜 | 生成、修改、镜头排序、重新生成指定镜头 | 多版本创意比较 |
| 画面生成 | 文字、图片、基本图形、图表、预设动画 | 复杂自定义组件、三维场景 |
| 实时可视化 | 默认观看画布、镜头、图层、音频、任务步骤；可切换人工接管 | 更细的差异高亮、性能与活动回放 |
| AI 工具操作 | MCP、内置多轮调用、原子剪辑、版本校验、取消与撤销 | 更多工具适配、跨工程复用与任务调度 |
| 图片能力 | 上传图片、一个生图适配器、重新生成与替换 | 多供应商路由、局部重绘、抠图 |
| 音频 | 导入、裁剪、音量、淡入淡出；本地、MiMo、OpenAI 兼容语音；AI 自动放置旁白 | 自动压低音乐音量、精细语音对齐 |
| 字幕 | 从脚本文字建立字幕、编辑内容和时间、样式预设 | 自动识别音频并对齐字幕 |
| 工程管理 | 自动保存、撤销重做、快照、工程包导入导出 | 团队空间、多人实时协作 |
| 渲染 | 同源预览、导出前检查、排队、取消、重试 | 批量导出和高级编码设置 |
| 模型配置 | 文本工具调用模型、生图、语音、模型列表、连接测试与次数上限 | 精确费用限制、多模型自动选择 |
| 代码能力 | 查看场景数据、导出配套源码与资产清单 | 受约束代码编辑、自定义组件开发 |

### 4.3 首版不纳入

多人实时协作、自动账号发布、数字人、自动电影制作、复杂三维编辑、完整专业剪辑器、任意代码的无损可视化逆向转换，以及无约束的联网资料搜集。

## 5. 端到端用户流程

### 5.1 从需求生成初稿

1. 用户新建项目，输入主题并可上传截图、标志、图片和音频。
2. 用户设置比例、时长、受众、语言、风格；未指定时使用可见默认值。
3. Agent 提取内容目标、事实、素材和缺失信息，形成需求摘要。
4. 系统生成脚本和分镜。每个镜头包含目的、文案、画面描述、时长、素材、字幕和旁白草稿。
5. Agent 简短说明计划后继续执行已授权制作，缺少必要产品事实时再请求补充，不要求逐个镜头人工确认。
6. Agent 通过工具逐镜头编辑结构化场景，设置时间和动画，按需生成并放置图片和旁白。
7. 每批有效操作校验后原子保存，实时广播镜头、图层、音频及执行状态，人在观看界面查看已完成部分。
8. Agent 定位预览、处理工具校验错误，按真实旁白时长调整画面。
9. 成片任务由 Agent 提交导出，界面继续显示渲染进度；人提出修改要求或在停止后人工接管。

当信息足以制作时继续执行；缺失的产品事实、真实数字和素材授权信息不由模型虚构。可用占位文案必须明确显示为待补充项。

### 5.2 自然语言局部修改

示例：“这个标题分成两行，字号小一点，提前半秒出现。”

1. 用户选中标题，Agent 上下文包含对象身份、所属镜头、当前属性和动画。
2. 对话输入区显示作用范围“当前标题”。
3. Agent 将指令转成局部变更，检查布局和时间是否有效。
4. 校验通过后整批应用，并刷新当前预览。
5. 操作历史记录修改内容，用户一次撤销即可恢复整个修改前状态。

没有选中对象且描述存在歧义时，Agent 先定位候选项，让用户选择；不能自行扩大到全项目。

### 5.3 修改镜头时长

示例：“第三个镜头增加两秒。”

默认将该镜头延长，并移动后续镜头，项目总时长同步变化。该镜头原有关键帧和字幕的局部起止时间默认保持不变；与镜头结尾绑定的出场动画随新结尾移动。缩短镜头导致字幕或关键帧越界时，按时间冲突规则处理，不能静默删除。

首版导入旁白与音乐按项目全局时间定位，不自动绑定镜头。改变镜头时长或顺序后，音频默认保持原位置，并提示用户检查旁白对齐；用户可以移动或裁剪音频片段。出现超出项目边界的情况时提供处理入口。

用户可以切换“保持总时长”，系统展示需要压缩的后续镜头及结果，再执行。不能同时默认承诺镜头延长和总时长不变。

### 5.4 生图与替换

默认由 Agent 根据镜头目标调用生图工具，把真实结果放入指定镜头并更新预览。人工接管入口仍允许编辑描述并生成、替换图片。候选图审核可作为用户指定的可选流程，不要求每次自动制作都等待手动选图。

用户确认的图片应复用于重复请求。模型失败时允许重试、上传替代图或改用图形版式。占位素材必须带有明确状态，导出前不能静默当作完成图片。

### 5.5 导出与再编辑

Agent 导出前检查规格、时长、素材和音频，修复阻断项，并创建使用指定工程版本的渲染任务。需要人补充事实或处理无法自动修复的问题时提供具体反馈。人工接管入口也可以独立导出。

渲染期间继续编辑会产生新版本，不改变正在渲染的内容。导出完成后可以下载视频，同时工程仍保留对象和时间线。

## 6. 工作台与页面需求

### 6.1 页面结构

| 页面 / 区域 | 主要内容 | 主要动作 |
| --- | --- | --- |
| 项目列表 | 名称、缩略图、比例、时长、更新时间、任务状态 | 新建、打开、复制、重命名、删除、导入工程 |
| 新建项目 | 需求、材料、视频规格、风格和模型选择 | 创建并生成、仅创建空工程 |
| 工作台顶部 | 项目名、保存状态、观看或接管状态、主题、导出 | 切换接管、主题、保存和导出 |
| 左侧镜头 / 素材区 | AI 更新的镜头顺序、缩略图、素材和图层 | 查看制作结构；接管后增删、排序和替换 |
| 中央画布 | AI 当前制作或检查的帧 | 默认观察与播放；接管后选中、拖动、缩放 |
| 底部时间线 | 实时镜头、对象、旁白和音乐片段 | 默认观察、定位和播放；接管后移动裁剪 |
| 右侧属性区 | 对象内容、位置、尺寸、样式和动画 | 查看属性；接管后精确修改 |
| AI 剪辑导演 | 目标输入、工具步骤、任务状态与导出进度 | 发起任务、停止、重试、连接外部 AI |
| 模型与项目设置 | 模型连接、费用上限、视频规格、字体和品牌样式 | 测试连接、选择能力、修改配置 |

工作台中的画布和时间线是人的主要观察区域，AI 剪辑导演是目标输入和任务控制入口。属性区与任务区可按需切换；默认观看模式应避免误触改动工程。MCP 接入窗口展示地址、连接类型、当前工程编号和可用配置。

### 6.2 交互要求

- 点击画布对象与点击图层条目应选中同一对象。
- 被选中对象的内容与时间线区间同步突出显示。
- 锁定图层不能被拖动，Agent 修改也需遵守锁定规则。
- 隐藏对象在预览和导出中一致隐藏。
- 属性编辑结束后立即更新画面，并记录一个可撤销操作。
- 连续拖动合并为一次操作，避免撤销需要反复点击。
- 移动时间线游标不修改工程，不进入撤销记录。
- 数值属性使用输入框或步进器；颜色使用色板；模式使用切换控件；工具使用图标并提供名称提示。
- 编辑过程中保持画布、时间线和工具按钮尺寸稳定。
- 空工程可手动添加首个镜头，不能强迫用户先调用模型。
- 默认观看，人工接管明确可见；内置 AI 运行期间先停止任务再接管。
- 实时工程更新不产生新的人类保存请求，避免事件同步与自动保存互相循环。
- 暗色和亮色主题只影响工作台，不能改变视频工程与导出画面；浏览器记忆主题选择。

### 6.3 必须具备的状态

项目为空、脚本生成中、画面生成中、部分完成、生成失败、保存中、保存成功、保存失败、资源加载中、素材失效、预览准备中、渲染排队中、渲染中、取消中、导出成功和导出失败。

错误提示应说明失败步骤、受影响对象及下一步操作，例如“第三个镜头的图片生成失败，可以重试或上传图片”。显示具体阶段和已完成镜头数，只有可测量的任务才展示百分比。

## 7. 功能详细规格

### F01：需求与输入材料，P0

**输入：** 用户描述、图片、截图、音频与项目参数。

**要求：**

- 文字输入支持至少 5,000 个中文字符；超限时给出明确提示。
- 首版图片格式为 PNG、JPEG、WebP；音频为 MP3、WAV、M4A。
- 首版建议单图片上限 20 MB、单音频上限 100 MB、工程资源总量上限 500 MB；服务端进行真实格式与解码检查。
- 从材料提取的内容与用户输入分开保存，并记录来源。
- 图片名称和用户提供的用途可帮助文本模型安排镜头；没有视觉能力的模型不能假装理解图片中的具体细节。
- 修改原始需求不会自动重写项目，用户需发起新的生成或修改任务。

**验收：** 输入描述和三张截图，可生成关联这些素材的分镜；损坏图片不会进入可导出的资源集合。

### F02：脚本与分镜，P0

每个分镜包含镜头身份、标题、目标、正文、画面说明、时长、素材引用、字幕、旁白草稿及信息来源。

- 允许直接修改文案和镜头顺序。
- 支持新增、复制、删除镜头，以及只重新生成一个镜头。
- 用户修改分镜后，相关画面显示“待同步”状态；同步时明确更新哪些对象。
- 总时长与所有镜头及转场的有效时长一致。
- 数字、产品功能、引用与结论必须可追溯到用户材料，新增假设需显式标记。
- 默认 AI 继续制作完整视频；用户明确要求审核分镜时再暂停等待，后续仍可提出修改。

**验收：** 删除第二个镜头后，播放顺序和项目总时长正确；其余镜头身份及素材引用不改变。

### F03：场景与标准对象，P0

首版标准对象包括文字、图片、矩形、圆形、线条、箭头、图形组、柱状图、折线图和数字展示。常用图标作为受控素材提供。

所有标准对象具有稳定身份、所属镜头、层级、位置、尺寸、旋转、透明度、显示区间及锁定状态。对象的内容、样式与动画独立保存。

| 类型 | 可编辑属性 |
| --- | --- |
| 文字 | 文案、字体、字号、字重、颜色、行高、文本框、对齐、换行 |
| 图片 | 绑定素材、缩放方式、裁剪区域、位置、尺寸、透明度 |
| 图形 | 填充、边框、尺寸、圆角、箭头端点 |
| 图表 | 数据、分类、坐标范围、颜色、标签、图例、出现顺序 |
| 图形组 | 组内对象、相对坐标、整体位置、整体动画 |

**验收：** 每种标准对象可以在画布和图层列表选中，修改后预览、保存重开和导出结果一致。

### F04：画布编辑，P0

- 支持位置拖动、缩放、旋转、文字内容编辑和图片裁剪。
- 属性面板支持精确坐标、尺寸和样式修改。
- 提供画面边界与安全区域；短视频平台的常见遮挡区域可以作为可选参考线。
- 文字过长时显示越界或截断提示，并提供自动换行或适配文本框操作。
- 首版自动文字布局以中文和常用拉丁文字为验收范围。
- 允许用户指定对象可以超出画布，用于入场或出场动画；检查不能把所有越界都判为错误。
- 对象基础变换与动画偏移分开保存。默认拖动修改基础位置，整体移动动画路径；启用关键帧记录后，拖动才修改当前帧的动画偏移。
- 属性面板明确区分基础属性与关键帧属性，播放位置变化不能隐式改变编辑模式。

**验收：** 拖动标题、更改字号并替换背景后，标题保持新的位置；快速连续拖动不引发对象跳动。

### F05：时间线与动画，P0

- 镜头轨支持排序、复制、删除和调整时长。
- 对象轨支持调整开始、结束与动画时间。
- 动画首版支持淡入淡出、平移、缩放、旋转、逐字出现、数字变化和简单图表增长。
- 关键帧首版支持位置、缩放、旋转和透明度，提供线性及缓入缓出曲线。
- 转场首版支持直接切换和交叉淡化，禁止超过相邻镜头可用时长。
- 同一镜头的入场和出场转场重叠长度之和不能超过该镜头持续帧数，首版不允许出现三镜头同时转场的情况。
- 改变对象显示区间时，不默认按比例改变所有关键帧；越界关键帧需提示裁剪、移动或缩放时间。
- 图层时间不超出所属镜头，特殊跨镜头视觉内容首版通过重复实例处理。
- 调整播放位置后，画面直接计算该帧状态，不依赖从头播放。

**验收：** 跳到第 300 帧与从第一帧播放到第 300 帧，所有对象的位置和透明度一致。

### F06：Agent 生成与修改，P0

Agent 可以创建镜头、增删对象、修改属性、设置动画、调整时间、替换素材和处理校验错误。每次任务绑定明确作用范围和起始工程版本。

- 普通局部修改校验成功后直接应用，可立即撤销。
- 用户明确要求重做、改变风格或调整结构时，Agent 按授权逐批提交，并显示步骤与结果；常规制作不依赖逐次人工应用。
- 已锁定对象和用户固定的属性默认不改；遇到冲突时提出具体冲突及处理选择。
- 简单的全局替换、统一颜色和顺序调整由确定操作执行，避免不必要的模型调用。
- 每个任务显示正在规划、生成场景、准备素材、检查、完成等阶段。
- 可停止任务；停止后取消未执行步骤，保留已提交的有效镜头。
- 有限自动修复：建议每个失败步骤最多两次修复，再显示错误和人工处理入口。
- 工具调用与修复次数受费用和执行时间上限约束。
- 支持外部 HTTP MCP 与内置多轮标准工具调用，工具名称、参数、结果和中文错误公开可读。
- 内置任务仅允许操作绑定工程；同一工程不并行运行多个内置任务；停止保留已提交剪辑。

**验收：** “把第二个镜头标题改成两行”只修改目标标题及确实需要的布局关联项；第一次撤销完整恢复。

### F07：图片上传与生图接入，P0

- 用户可配置一个生图服务，项目可选择完全不使用生图。
- 生图任务记录提示词、尺寸、服务、模型、请求身份、状态、结果与费用信息。
- 生成成功后资源下载到受管理存储，不长期依赖可能失效的外链。
- 图片用资源身份引用；更换图片不改变对象身份、位置和时间。
- 按镜头比例提出尺寸要求，供应商不支持时以裁剪或留边处理，并提供预览。
- 品牌标志、准确文案和图表标签优先由可编辑对象叠加，不依赖生图模型把文字画准确。
- 单张图片内部内容不能被普通图层编辑；用户可以重新生成、替换和裁剪。
- 默认一次生成一个真实结果，由 AI 绑定并显示在镜头中；用户要求多候选审核时再进入选择流程，调用仍受次数和费用限制。
- 已完成的图片不会因普通文案调整而重新生成。

**验收：** 生图服务中断后仍可以使用上传图片完成预览和导出；图片外链过期后已保存素材仍可使用。

### F08：音频与字幕，P0

- 用户可导入一条旁白轨和多条音乐片段，支持裁剪、移动、音量、静音、淡入淡出。
- 旁白和音乐使用全局时间，首版不随镜头排序自动移动。需要逐镜头旁白绑定时，将其作为后续增强能力。
- 无音频时允许导出，并在导出设置中明确显示“无音频”。
- 脚本生成旁白文字后，Agent 可调用本地或用户配置的语音服务，只有取得实际音频素材才显示生成成功。
- 从脚本生成字幕时，首版按镜头和文本长度分配初始时间，标记为可调整结果。
- 未接语音识别或强制对齐能力时，不承诺字幕与上传旁白逐词准确同步。
- 音频时长超过项目时长时，让用户选择裁剪、移动、延长项目或禁用该片段。
- 字幕具有内容、开始帧、结束帧、样式和所属镜头，可在字幕列表与时间线编辑。
- 字幕可导出为单独的字幕文件，建议作为 P1。

**验收：** 上传 60 秒旁白到 45 秒项目时显示时长冲突；用户裁剪后，视频和音频结束位置正确。

### F09：保存、历史与工程包，P0

- 本地即时记录操作，后台自动保存；页面显示最近一次成功保存的状态。
- 撤销重做覆盖用户操作和已应用的 Agent 变更，不覆盖播放操作。
- 支持手动快照，并在完整生成、全局修改与导出前记录版本。
- 模型对话和工程操作分开存储；删除对话不删除项目历史。
- 导出工程包包含场景数据、资源文件、字体依赖或引用、渲染版本与资源清单。
- 同时提供适配工程的渲染源码包；可独立运行程度取决于包内依赖和实际资源许可。
- 重新导入工程时校验格式版本、缺失资源和组件版本，列出需修复项。
- 工程包和源码包不包含 API 密钥、用户令牌或服务端配置。

**验收：** 工程包在新建工作区导入后，镜头、图层、素材、关键帧和字幕仍可编辑；缺失字体提供可定位的替换操作。

### F10：预览、检查与导出，P0

- 预览和导出使用同一场景数据、字体、布局逻辑、组件版本和帧计算方法。
- 预览可降低显示分辨率、关闭编辑辅助线，但不能改变内容与时间。
- 渲染任务绑定不可变工程版本和资源版本。
- 支持任务排队、查看阶段、取消、重试和下载。
- 取消后停止可取消的工作，删除不完整导出文件，不删除工程。
- 服务重启后能识别中断任务并重试，避免永远显示“渲染中”。

| 检查级别 | 检查内容 | 处理方式 |
| --- | --- | --- |
| 阻断 | 数据结构不合法、必需素材缺失、字体未准备、时长为零、组件不可执行 | 必须修复后导出 |
| 提示 | 文字可能溢出、字幕可能重叠、音频超界、占位素材、低分辨率图片 | 定位问题，可修复或按规则明确接受 |
| 信息 | 无音频、降低分辨率、使用替代素材 | 展示事实，允许继续 |

检查不是对所有视觉问题的保证。复杂遮挡、语义错误和艺术效果仍需要人工预览。

### F11：模型与费用配置，P0

- 文本模型与生图模型分别配置。
- 文本模型必须支持文本输出；结构化输出可以通过协议能力或系统校验实现。
- 内置自主 Agent 要求模型支持标准工具调用；不支持时明确提示兼容性错误，不把普通文字回应伪装成执行成功。以后若增加动作 JSON 适配，应显式标记并单独验收。
- 优先提供兼容常见文本接口协议的适配器，但生图接口需要各供应商独立适配，不能承诺填写任意地址即可通用。
- 显示连接测试结果、支持能力、超时和错误原因。
- 支持自有密钥，密钥保存在服务端并加密，客户端只能查看脱敏状态。
- 任务设置费用上限和最大调用次数。供应商不提供价格或用量时显示“无法精确估算”，不能显示虚假的零成本。
- 重试前检查任务身份与已有结果，避免重复收费和重复绑定素材。

**验收：** 更换文本模型后，已有工程可继续编辑和导出；删除模型配置后，工程不丢失。

## 8. 可编辑性的底层约束

### 8.1 唯一项目事实源

建议使用结构化场景文档作为唯一项目事实源。画布、时间线、属性面板、Agent 和渲染器读写同一份数据。

文本模型可以生成场景数据、动画方案和受约束代码，但只有通过结构、能力、资源和时间校验的结果才能进入工程。

不能把任意生成代码自动等同于可视化可编辑工程。若直接把所有画面写在自由代码中，系统通常无法稳定识别标题、图层、镜头和时间线，也无法可靠地把鼠标操作写回代码。

### 8.2 三种编辑层级

| 层级 | 内容 | 可视化能力 | 发布阶段 |
| --- | --- | --- | --- |
| 标准场景 | 受控文字、图片、图形、图表、预设动画 | 全部标准属性、内容和时间可编辑 | P0，默认生成路线 |
| 参数化组件 | 自定义动画组件暴露明确参数 | 位置、尺寸、时间及公开参数可编辑 | P1 |
| 自由代码 | 用户或模型提供的任意实现 | 只能保证外层容器及显式公开参数可编辑 | P2，独立高级模式 |

首版代码视图用于查看和导出；不提供任意代码编辑后无损回到图层的承诺。后续开放代码编辑时必须限定语法或明确组件内部编辑边界。

### 8.3 手动修改与锁定

手动改变的属性记录来源和修改版本。后续 Agent 任务可以读取这些属性，但不能因重建镜头而无意覆盖。

普通手动属性允许用户明确要求修改。显式锁定的对象或属性只有用户解锁或明确授权解除锁定后才能变化。

冲突示例：用户锁定了标题字号和文本框，但要求放入更长文案。系统应显示溢出冲突，给出缩短文案、扩大文本框或解除字号锁定的选择。

## 9. Agent 工作机制

### 9.1 职责划分

| 职责 | 输入 | 输出 | 限制 |
| --- | --- | --- | --- |
| 需求规划 | 用户需求和材料 | 内容目标、事实、风格与约束 | 不编造产品事实 |
| 脚本与分镜 | 规划结果 | 文案、镜头结构、时间安排 | 遵守时长和镜头上限 |
| 场景制作 | 镜头描述和组件目录 | 场景数据与动画参数 | 只使用允许的对象和能力 |
| 素材调度 | 素材需求 | 上传素材绑定或生图任务 | 遵守费用和请求限制 |
| 工程校验与修复 | 候选修改、校验结果 | 合法补丁或错误报告 | 有限重试，不能绕过约束 |

这些是任务职责，不要求首版部署五个独立模型或五个同时运行的代理。简单任务可以由一个模型分步骤完成，并由程序负责校验和调度。

### 9.2 修改事务

每次 Agent 修改至少记录任务身份、起始版本、作用范围、候选补丁、校验结果、费用、最终版本和操作摘要。

提交步骤：读取最新工程 → 理解范围 → 调用局部剪辑工具 → 原子校验与提交 → 保存版本 → 记录撤销与实时广播。工具错误作为结果返回给 AI，允许它修正后重试。

部分属性修改失败时，不应先提交一半再让工程处于矛盾状态。初稿生成可以按镜头逐步提交，每个镜头提交自身完整有效的结果。

### 9.3 与用户并行编辑

首版默认观看，内置 AI 运行期间需要先停止再人工接管。外部 AI 与其他客户端仍可能产生并发更新，每次剪辑提交必须携带读取时的 `revision`：

- 起始版本落后于当前版本时拒绝整批修改，AI 重新读取工程后修正。
- 不自动合并不同对象或不同属性，避免忽略布局、时间和顺序依赖。
- 人工未保存草稿与服务端更新冲突时显示提示，不能静默覆盖草稿。
- 人工接管只改变本工作台操作权限，外部 AI 需在其客户端停止。

对象级合并可作为后续能力，需单独验证依赖和保护规则。

### 9.4 无视觉模型也能工作

核心流程不依赖模型读取截图。文字边界、画布范围、资源加载、关键帧有效性和时间冲突通过程序检查；画面效果由用户预览确认。

可选的视觉模型可以辅助检查截图与理解上传图片，但应独立标记为增强能力，关闭后仍能完成核心任务。

### 9.5 外部工具与实时观察

HTTP MCP 端点为 `/mcp`，提供初始化、工具列表、工具调用和存活检查；内置 Agent 使用同一工具目录与执行实现。外部 AI 可以读取或新建工程，并操作镜头、图层、音轨、图片、旁白、预览和导出。内置任务绑定已有工程，不允许另建或操作其他工程。预览工具生成实际指定帧截图，可选向具有视觉能力的 MCP 模型附加图片；纯文本模型不假装完成视觉理解。

人的工作台通过 `/api/projects/{id}/events` 的服务端事件流接收变化，连接时取得当前工程快照，重连时同步最新保存版本。MCP 调用通道与画布事件通道各自承担工具执行和实时观察；不依赖 AI 模拟鼠标操作。

内置任务上限为 20 轮模型调用、40 次工具调用和 15 分钟，任务记录持久化。宣传片、成片与导出任务结束前必须提交导出；导出返回编号后由界面跟踪渲染。任务停止保留已提交工程，已经提交的导出独立取消。服务重启将未完成内置任务标记为中断失败。

## 10. 工程数据规格

### 10.1 主要实体

| 实体 | 关键数据 | 关系 |
| --- | --- | --- |
| 项目 | 身份、名称、画布、帧率、语言、主题、当前版本 | 包含镜头、资源和音频 |
| 镜头 | 身份、顺序、持续帧数、分镜内容、背景、转场 | 包含视觉对象与字幕 |
| 视觉对象 | 身份、类型、父对象、位置、大小、样式、显示区间、锁定 | 引用素材与动画 |
| 动画 | 属性、关键帧、缓动、预设参数 | 绑定对象或组件 |
| 资源 | 身份、版本、文件位置、类型、尺寸、校验值、来源 | 被对象和音频引用 |
| 字幕条目 | 文字、开始帧、结束帧、样式、镜头身份 | 引用脚本来源 |
| 音频片段 | 资源、项目起始帧、源文件裁剪范围、音量、淡入淡出 | 位于旁白轨或音乐轨 |
| 项目版本 | 版本身份、父版本、场景快照或变更记录、时间 | 绑定导出任务 |
| Agent 任务 | 需求、范围、起始版本、步骤、状态、费用 | 产生变更与素材任务 |
| 渲染任务 | 项目版本、规格、状态、资源快照、输出 | 使用固定版本渲染 |

### 10.2 时间与坐标规则

- 工程时间统一存储为整数帧，首版每秒 30 帧。
- 镜头内对象和字幕使用镜头局部时间；音频使用项目全局时间。
- 区间统一为包含开始帧、不包含结束帧，避免相邻区间重复一帧。
- 镜头起始位置从顺序、持续帧数和转场重叠推导，不重复存储另一套可冲突的时间。
- 项目总帧数等于镜头帧数之和减去转场重叠帧数。
- 持续帧数、转场长度和关键帧位置都必须为有效整数。
- 画面坐标使用项目画布单位；对象组内部使用相对坐标。
- 随机效果如确有需要，使用保存的随机种子；渲染不能依赖当前系统时间。
- 导入不同采样率音频时统一处理，不改变工程帧率。

### 10.3 数据版本与资源追踪

场景格式、组件、渲染器和字体均记录版本。资源替换建立新版本，已提交工程版本仍能引用旧资源。项目删除前，资源清理需检查其他版本与项目是否仍在引用。

源素材、生成提示词、用户修改和模型生成内容记录来源，便于用户解释结果和复用工程。

## 11. 建议技术架构

### 11.1 架构分层

| 层 | 建议方案 | 责任 |
| --- | --- | --- |
| 观察与接管前端 | React 与类型约束，画布、时间线、任务记录和属性面板 | 实时观察工程，按需人工接管 |
| Go 项目服务 | 工程文件、修订号、资源和操作接口 | 保存唯一工程数据，处理版本冲突 |
| Go AI 工具服务 | HTTP MCP、工具目录、原子剪辑与校验 | 向内置与外部 AI 暴露实际操作能力 |
| Go Agent 编排服务 | 模型适配器、多轮工具调用、任务状态机与取消 | 执行自然语言目标，反馈工具结果 |
| 实时事件服务 | 工程快照、剪辑事件、预览定位和任务状态 | 向人的浏览器推送可观察过程 |
| 场景渲染层 | 优先评估 Remotion 与受控 React 组件 | 按指定帧计算文字、图形和动画 |
| 渲染工作节点 | 隔离浏览器渲染、编码工具、任务队列 | 生成视频、截图和音频输出 |
| 资源服务 | 文件存储、缩略图、字体与生成图片管理 | 确保预览和导出能取得相同素材 |
| 外部模型层 | 工具调用文本模型；生图可选；本地及远程语音；视觉可选 | 提供生成能力 |

Remotion 是用于以 React 组件组织并渲染视频的工具，适合程序化视频，但需要通过原型验证中文排版、性能、依赖和使用条款。它是渲染执行层，不能替代项目数据和可视化编辑器。

### 11.2 推荐实现路线

第一阶段向 AI 暴露读取工程、局部剪辑、素材、旁白、预览和导出工具，由多轮调用逐步制作结构化场景，使用已实现组件。先保证每个操作可校验、可保存、可实时观察，画面对象可编辑和渲染稳定。

第二阶段加入参数化组件，让代码模型实现受约束的复杂图形和动画；组件必须声明参数、资源、尺寸、时间和支持的编辑能力。

第三阶段再考虑高级代码模式。自由代码在隔离环境中执行，不能接触服务密钥、任意网络、宿主文件系统或无限计算资源。

### 11.3 部署与任务恢复

建议首版采用单一网页应用与后端服务，渲染工作节点独立运行，使用持久任务队列。数据库保存项目和任务，文件存储保存素材与导出物。

开发和试用环境可在本机启动服务；正式部署允许将渲染节点迁移至服务器。离线模型接入与完整私有化安装包列为后续能力，不与首版混合承诺。

任务状态至少包括排队、运行、等待用户、成功、失败、取消中和已取消。外部模型调用不可即时撤回时，停止后忽略迟到结果，且不再发起后续步骤。

## 12. 预览与视觉检查

### 12.1 一致性要求

预览与导出必须共用同一镜头求值逻辑。文字不能在浏览器预览时用一种字体、导出时用另一种字体。所有必需字体和素材准备完成后才开始正式导出。

编辑选框、网格、安全线和状态标签属于工作台，不进入视频。预览缩放不参与文字布局计算。

### 12.2 检查采样

每个镜头检查开头、中间、末尾有效帧，并追加动画关键帧、转场附近和文字完整显示时刻。采样截图可以发现明显空白或加载失败，但不能保证发现所有中间帧问题。

程序检查对象边界和遮挡关系时区分有意叠加与疑似问题。背景、字幕、安全区域和装饰图形采用不同检查规则。

### 12.3 检查结果交互

点击问题后定位镜头、时间与对象，提供对应处理操作。自动修复只能改变获准范围，处理后重新校验，不能为了消除提示而删掉用户内容。

## 13. 性能与非功能要求

### 13.1 原型测试基线

建议使用 60 秒、6 个镜头、100 个标准对象、10 张本地图片、一条旁白、一条音乐、一个中文字体的工程进行测量。预览和导出分别记录设备、浏览器、渲染节点配置及组件版本。

建议初始渲染测试环境为 8 个虚拟处理器、16 GB 内存、无独立显卡的 Linux 节点。实际性能需根据字体、图表、滤镜和素材尺寸压测。

| 项目 | 规划目标 | 说明 |
| --- | --- | --- |
| 常用属性编辑反馈 | 95 分位数低于 150 毫秒 | 不包括素材下载和模型调用 |
| 定位帧后的画面更新 | 95 分位数低于 500 毫秒 | 素材和字体已加载 |
| 基线工程预览 | 接近 30 帧/秒，明显卡顿时提供降级预览 | 性能不佳不能修改实际工程时间 |
| 本地操作恢复 | 页面刷新后恢复最近已记录操作 | 服务保存失败也应有本地恢复入口 |
| 模型等待 | 分别记录规划、分镜、场景、生图耗时 | 不以固定时限掩盖供应商差异 |
| 正式导出 | 先记录每分钟视频所需时间与失败率 | 原型后确定可承诺目标 |

### 13.2 稳定性

- 刷新页面不丢失已提交工程和正在执行的后台任务。
- 网络中断时显示保存状态并保留本地操作，重新连接后处理版本冲突。
- 模型超时、格式错误、生图失败和编码失败分别有恢复入口。
- 不完整素材不能伪装成准备完成。
- 自动保存失败不应显示“已保存”。

### 13.3 数据与执行边界

- 模型只能调用注册工具和获准资源，用户上传的文本与模型输出不能直接改变系统权限。
- 生成代码和媒体解码使用隔离环境及资源限额，避免错误代码拖垮整个服务。
- 模型密钥不发送到渲染页面、工程包或日志。
- 工作节点访问素材使用受限资源凭证。
- 对用户材料提供删除操作，明确项目、导出物和历史快照的保留规则。
- 日志记录任务身份和错误类别，默认避免记录完整密钥与无必要的私人材料。

### 13.4 易用性与无障碍

表单和编辑控件提供清楚名称，状态不只靠颜色区分。文本与按钮在桌面不同窗口宽度下不重叠。界面以中文为默认语言，专业参数配有中文名称。

## 14. 商业与资源控制建议

商业模式先选择“自有密钥试用 + 明确的渲染资源限制”，验证制作价值后再考虑平台提供模型额度的套餐。

费用由文本模型、图片生成、渲染计算、存储和下载构成，应分别记录。首版不虚构统一的“每个视频固定成本”。

如果平台承担调用费用，导出前与高成本素材生成前应展示实际可估算部分，设置单任务、单用户与日预算上限。简单编辑与再次打开已有工程不需要模型调用。

模板和动画组件复用、已确认素材复用、局部修改、缓存与减少重复生成，是降低成本的主要方向。

## 15. 验收场景

使用固定材料和固定工程建立验收集。模型生成措辞可以有变化，但不能因此降低可编辑性、范围正确性和导出完整性要求。

| 编号 | 场景 | 必须满足 |
| --- | --- | --- |
| A01 | 没有生图、语音、视觉与视频模型，只接文本模型 | 完成文字、图形、图表组成的可编辑短视频并导出 |
| A02 | 输入产品说明与三张截图 | 至少 3 个镜头，素材关联正确，内容不虚构功能 |
| A03 | 选中标题后要求换行、缩小、提前出现 | 仅修改获准对象及必要依赖，撤销完整恢复 |
| A04 | 用户移动标题后要求更换背景 | 标题位置保持不变 |
| A05 | 延长第三个镜头两秒 | 后续镜头按规则移动，总时长和字幕时间一致 |
| A06 | 生图失败 | 工程仍可编辑，支持替代图，不丢失已完成镜头 |
| A07 | 替换图片资源 | 对象身份、裁剪以外的布局和时间保持一致 |
| A08 | Agent 运行期间用户修改同一标题 | 识别版本冲突，不覆盖用户修改 |
| A09 | 字体或必需素材缺失 | 导出前阻断并定位问题，修复后可继续 |
| A10 | 导出期间继续编辑 | 输出使用任务绑定版本，新编辑保存为后续版本 |
| A11 | 工程保存、关闭、重开及工程包导入 | 所有标准对象、字幕与关键帧继续可编辑 |
| A12 | 取消正在生成的任务 | 保留已提交镜头，迟到结果不覆盖新任务 |
| A13 | 从开始播放与直接跳转到指定帧 | 布局和动画状态相同 |
| A14 | 预览与导出抽取相同帧 | 文字、布局、图层顺序和时序一致；压缩差异另行评估 |
| A15 | 项目达到上限 | 清楚提示限制，不损坏已有工程 |
| A16 | 用户输入长中文标题、混合数字和标点 | 文字不静默截断，溢出可识别、可处理 |
| A17 | 服务重启或渲染节点异常 | 任务可识别为中断并恢复，不永久停在运行状态 |
| A18 | 更换或移除模型配置 | 已有工程仍能手动编辑与导出 |
| A19 | 外部 AI 通过 HTTP MCP 接入 | 读取工具与工程，实际剪辑后浏览器自动显示新版本 |
| A20 | 内置模型只返回文字，没有工具调用 | 明确兼容性失败，不显示剪辑成功 |
| A21 | AI 制作宣传片 | 按工具逐步编辑与安排音频，提交导出，实际可播放后才认定成片完成 |
| A22 | 默认观看切换人工接管 | 观看时不会误改工程，运行期间需先停止，接管后修改可保存 |
| A23 | 服务端事件断线重连 | 同步最新工程，不重复保存事件带来的变更 |
| A24 | 暗色模式和重新打开 | 主题记忆正确，文字与控件可读，导出画面颜色不受主题影响 |

预览与导出一致性不以视频压缩后逐像素完全相同为标准。先比较无损采样帧的布局和时间，再检查正式视频的编码质量与音画同步。

## 16. 主要风险与处理

| 风险 | 对产品的影响 | 处理方案 |
| --- | --- | --- |
| 模型生成任意代码，无法映射为图层 | 可编辑性成为空承诺 | 首版使用结构化场景与受控组件 |
| 自动初稿能播放但质量普通 | 用户仍需要大量重做 | 先聚焦信息类题材，建立少量高质量版式与动画组件 |
| Agent 全量重写导致用户修改丢失 | 用户不再信任 AI 修改 | 稳定对象身份、局部补丁、锁定和版本冲突处理 |
| 中文字体与排版差异 | 预览正常、导出溢出 | 固定字体资源与布局逻辑，建立长中文验收集 |
| 生图中出现错误文字或不可控细节 | 品牌和信息不准确 | 文字、标志和图表由编辑对象叠加，图片作为素材层 |
| 字幕时长与旁白不匹配 | 观看体验差 | 明确首版初始时间规则，支持手动对齐，后续接入识别能力 |
| 渲染资源消耗过高 | 等待过久、成本不可控 | 工程限额、任务队列、组件性能基线和缓存 |
| 外部供应商失败或价格未知 | 生成不完整、费用不透明 | 能力适配、分步恢复、限额和未知价格提示 |
| 误以为所有视频类型都能制作 | 用户预期与实际能力冲突 | 示例和入口围绕程序化、信息类视频展示真实能力 |

## 17. 里程碑与交付物

以下是建议顺序，实际时间取决于团队规模、已有基础与原型结果。以 3 至 5 人小团队估计，首版验证周期可先按 10 至 14 周规划。

| 阶段 | 建议时间 | 交付物 | 进入下一阶段的条件 |
| --- | --- | --- | --- |
| 技术与产品原型 | 1 至 2 周 | 一份场景文档、中文文字/图片/图表镜头、基础预览与导出 | 同一工程可编辑并稳定渲染，确认技术与依赖可用 |
| 手动编辑闭环 | 2 至 3 周 | 画布、属性、时间线、撤销、保存、版本与工程包 | 没有模型时也能完成基础视频 |
| Agent 闭环 | 3 至 4 周 | 需求生成、分镜、局部补丁、范围控制、校验与恢复 | 生成初稿与修改不破坏工程 |
| 素材与完整输出 | 2 至 3 周 | 生图适配、音频、字幕、导出检查、任务队列 | 从输入到导出的核心验收场景通过 |
| 内测与稳定性 | 约 2 周，可与末阶段部分并行 | 固定验收集、性能与成本报告、用户任务观察 | 明确成功率、主要失败类型和可承诺规格 |

需要覆盖的职责包括前端编辑器、渲染与工程数据、Agent 与后端、产品交互，以及测试与运维。一个人可以承担多个职责，但不应把数据一致性和任务恢复视为上线后再补的功能。

## 18. 后续演进

### 18.1 第一阶段之后

增加品牌样式保存、模板复用、字幕导出、更丰富的语音控制、音频自动对齐、图表类型、批量属性编辑与受约束自定义组件。

### 18.2 再下一阶段

增加团队空间、审核流程、批量生成、更多素材供应商、组件市场、私有化部署和高级代码模式。

高级代码模式应通过明确的组件接口暴露可编辑参数。它的验收标准不能与标准对象的完整可视化编辑混为一谈。

## 19. 首版前需要验证的决策

以下事项不会阻碍原型开始，但应在正式开发范围冻结前确认。

1. 首批用户更偏产品运营还是知识创作者，从中选出一个主要场景。
2. 主要部署是本地试用、私有服务还是云端服务，对应资源存储与密钥配置方式。
3. 是否由平台承担模型费用，还是首版只支持用户自有密钥。
4. 已确认本地与远程语音合成；需继续明确默认音色、实际音质与供应商失败处理。
5. 默认视频时长、主要比例及可接受的导出等待时间。
6. 代码模式是否是核心卖点；如果是，先确定参数化组件接口，而非承诺任意代码可逆。
7. 是否需要用户上传录屏；如果需要，增加视频素材解码、裁剪和时间线规则。

## 20. 首版完成定义

用户无需写代码或逐片段手动编排，只需描述目标，AI 通过 MCP 或内置工具调用完成信息类短视频制作；人的画布、时间线与步骤记录实时同步；可以停止任务和人工接管；文字、图片、图形、图表与音轨保持明确对象身份；锁定和手动保护不被无意覆盖；工程能保存、重新打开和打包；预览与导出使用同一内容和时间逻辑；素材、模型或渲染失败时有可执行的恢复路径。

达到这些条件后，再扩大视频题材、模型数量和高级编辑能力。

## 21. 新增确认需求：配音、模型列表与片段编辑

日期：2026-10-09。以下要求提升为首版功能。

### 21.1 三种配音来源

- 本地默认 TTS：不需要远程密钥，生成可保存、可导出的普通话音频。基础本地音色可以是机械合成音色，界面应明确展示实际来源。
- 小米 MiMo：按照官方 MiMo-V2.5-TTS 协议接入，支持预置音色和音色设计。合成文本置于 assistant 消息，风格描述置于 user 消息，Base64 音频保存为项目素材。
- OpenAI 兼容接口：支持配置服务地址、密钥、模型、音色和语速，通过 audio/speech 接收音频文件。

人工配音入口可以先试听再加入时间线；默认 AI 流程调用工具真实合成并放置音轨，按实际时长编排画面。音轨具有位置、源素材起点、片段时长、音量、淡入和淡出，可在预览和视频导出时使用。切换远程供应商后必须保存对应配置，避免向错误的服务发送请求。没有实际密钥调用时，只能报告协议验证结果。

### 21.2 获取模型列表

文本、生图和远程 TTS 设置分别提供获取模型列表操作，使用当前填写的地址和密钥请求供应商 models 接口。获取列表不自动保存配置，也不覆盖用户已经填写的模型名称。列表可选择，模型名称仍支持手动填写。

本地 TTS 无需远程模型列表。供应商不支持列表接口或鉴权失败时，显示实际错误，不伪造可用模型。

### 21.3 时间线片段操作

每个镜头、图层和音频片段都可通过 AI 工具调整；人实时观察结果，人工接管时也能在时间线上操作，并使用精确属性编辑入口。

- 镜头主体拖动调整连续排列顺序，左右边缘调整时长与裁剪区间。
- 图层片段主体拖动改变显示时间，左右边缘调整开始和结束帧，范围保持在所属镜头内。
- 音频主体拖动改变全局播放位置，左右边缘调整源素材截取范围和片段长度。
- 一次连续拖动记录为一次可撤销操作；保存和再次打开后保留结果。
- 裁剪不能改变或删除源素材文件，非法区间和超限工程需拒绝应用。

当前标准场景由程序渲染；录屏与普通视频素材的专业剪辑仍按照后续范围处理。

## 22. 新增确认需求：AI 操作、实时观看与暗色模式

日期：2026-10-09。默认产品流程调整为 AI 使用工具剪辑，人通过可视化观看。第 1、5、6、9、11 节按这一定位更新。

### 22.1 AI 工具接入

- 外部 AI 使用本机 HTTP MCP `/mcp`，无需通过鼠标自动化控制页面。
- 内置 AI 使用支持标准工具调用的文本模型，多轮执行同一工具目录；每轮工具返回实际结果和校验错误。
- 工具覆盖工程读取与创建、镜头与图层编辑、片段移动裁剪、音频安排、生图、TTS、预览定位和 MP4 导出。
- 内置任务限定目标工程；版本冲突拒绝整批提交，重新读取后再试。
- 不支持工具调用的模型明确失败，不把计划、纯文字或工程 JSON 当作已经剪辑。

### 22.2 实时观看与人工接管

- 工作台默认观看，SSE 推送每次有效剪辑、工程快照、AI 步骤与预览位置。
- 人输入目标和修改要求，不需要手动批准每个常规工具动作。
- 人工接管作为可选操作保留；内置任务先停止，再编辑；继续 AI 前保存人工改动。
- 外部 AI 需在外部客户端停止，工作台按钮不能代表已取消外部进程。
- 保存工程、停止 AI、取消导出分别展示实际状态，不相互冒充。

### 22.3 暗色模式

亮色与暗色工作台保持相同布局、状态和控件能力。首次访问跟随系统，手动选择保存到当前浏览器。主题不得影响工程色值、媒体素材或导出结果。桌面及窄屏均需验证文字对比、时间线标签、选中状态、弹窗和输入控件。

### 22.4 实际验收要求

模拟工具调用测试和早期编辑器验收不能代替本次端到端验证。外部 MCP 客户端接入、真实已配置模型宣传片、实时观看与接管、断线恢复和暗色模式均需留下独立验收证据。真实远程配音、生图及最终 MP4 输出应分别检查；尚未执行的项目在实现说明中明确标记待验收。
