# 完整工作台安装部署

本指南安装可连接 AI、编辑工程、生成素材并导出视频的完整映序工作台。推荐 Linux 本机运行，或在自己的 Linux 服务器上运行后通过 SSH 隧道访问。

## 运行依赖

| 依赖 | 用途 |
| --- | --- |
| Go 1.22 或更新版本 | 编译与运行后端 |
| Node.js 22 与 npm | 构建前端、运行预览和导出脚本 |
| FFmpeg 与 FFprobe | 编码视频、检测与混合音频 |
| Playwright Chromium | 渲染预览截图与视频帧 |
| 中文字体 | 正确显示和导出中文文字，Linux 推荐 `fonts-noto-cjk` |
| espeak-ng，可选 | 本地普通话配音；使用远程语音服务时可不安装 |

目前以 Linux 为主要运行环境，渲染进程管理依赖 Unix 机制。Windows 建议使用安装了上述依赖的 WSL2 Linux 环境。仓库未提供 Dockerfile 或 Compose 配置，本指南不假定已支持开箱即用的容器部署。

先通过系统包管理器或官方发行包安装 Go 与 Node.js，并确认：

```bash
go version
node --version
npm --version
```

Debian / Ubuntu 的媒体和字体依赖：

```bash
sudo apt-get update
sudo apt-get install -y git ffmpeg espeak-ng fonts-noto-cjk
ffmpeg -version
ffprobe -version
espeak-ng --voices=cmn
```

## 本地启动

```bash
git clone https://github.com/zhangjiabo522/agentvideo.git
cd agentvideo
npm ci
npx playwright install chromium
npm run start
```

打开 [http://127.0.0.1:8080](http://127.0.0.1:8080)。首次运行会构建前端，工程数据默认保存在仓库的 `data` 目录。保持终端运行，按 `Ctrl+C` 停止服务。

若 Chromium 报缺少系统库，在 Debian / Ubuntu 上运行：

```bash
npx playwright install --with-deps chromium
```

浏览器应由启动映序的同一系统用户安装。切换运行用户后，原用户缓存中的浏览器可能无法被发现；可以重新安装，或通过 `CHROME_PATH` 指向可访问的 Chromium 可执行文件。

若 Go 不在 `PATH` 中，可以使用启动脚本的 `GO_PATH`：

```bash
GO_PATH=/实际路径/go/bin/go npm run start
```

`npm run setup:tts` 只适用于具备 `libespeak-ng1`、`espeak-ng-data` 和 Debian 包工具的 Linux 环境，它会将语音程序解包到本地缓存；它不会替代系统运行库安装。能使用包管理器时，直接安装 `espeak-ng` 更简便。

## 构建后运行

长期运行可以先构建后端二进制，避免每次启动时编译：

```bash
npm ci
npm run build
mkdir -p bin
go build -o bin/yingxu ./cmd/server
./bin/yingxu -addr 127.0.0.1:8080 -data data -dist dist
```

请在仓库根目录运行。完整工作台除 `bin/yingxu` 和 `dist` 外，还需要 `scripts`、`node_modules`、可用的 Node.js、FFmpeg、FFprobe 与 Chromium。Playwright 位于开发依赖中，因此运行环境需要完整 `npm ci`，不能仅安装生产依赖。

健康检查：

```bash
curl --fail http://127.0.0.1:8080/api/health
```

响应的 `ok` 表示服务可响应；`ffmpeg` 检查 FFmpeg，`renderer` 检查 Node.js 与渲染脚本，`localTts` 检查本地语音程序。这些检查不会实际启动 Chromium，最终应生成一张预览或导出一支短片确认媒体链路。

## 配置路径与端口

| 配置 | 默认值与用途 |
| --- | --- |
| `VIDEO_ADDR` 或 `-addr` | `127.0.0.1:8080`，服务监听地址 |
| `VIDEO_DATA` 或 `-data` | `data`，工程、素材、任务和模型设置目录 |
| `-dist` | `dist`，前端构建目录 |
| `VIDEO_ROOT` | 当前工作目录，定位渲染、截图脚本和本地 TTS 缓存 |
| `RENDER_ORIGIN` | 默认根据请求端口使用本机地址；代理或隧道端口不一致时指定服务实际本机地址 |
| `CHROME_PATH` | 可选，指定 Chromium 可执行文件 |
| `LOCAL_TTS_PATH` | 可选，指定 `espeak-ng` 可执行文件 |
| `GO_PATH` | 仅启动脚本使用，指定 Go 可执行文件 |

示例使用另一个端口和独立数据目录：

```bash
VIDEO_ADDR=127.0.0.1:8081 VIDEO_DATA=/实际路径/yingxu-data RENDER_ORIGIN=http://127.0.0.1:8081 npm run start
```

`RENDER_ORIGIN` 应指向运行服务自身能够访问的本机地址，例如 `http://127.0.0.1:8080`。

## Linux 常驻服务

以下使用当前普通用户的 systemd 服务，假定仓库位于 `~/agentvideo`，已经完成构建，并且当前用户可以直接执行 `node`、`ffmpeg` 与 `ffprobe`。若仓库路径不同，请同步替换单元文件中的路径。

```bash
mkdir -p ~/.config/systemd/user
```

创建 `~/.config/systemd/user/yingxu.service`：

```ini
[Unit]
Description=映序视频工作台
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
WorkingDirectory=%h/agentvideo
Environment=VIDEO_ROOT=%h/agentvideo
Environment=RENDER_ORIGIN=http://127.0.0.1:8080
Environment=PATH=%h/.local/bin:/usr/local/bin:/usr/bin:/bin
ExecStart=%h/agentvideo/bin/yingxu -addr 127.0.0.1:8080 -data %h/agentvideo/data -dist %h/agentvideo/dist
Restart=on-failure
RestartSec=3
UMask=0077

[Install]
WantedBy=default.target
```

通过 nvm 等工具安装 Node.js 时，先执行 `command -v node`，把结果所属目录加入单元的 `PATH`。systemd 不会自动加载交互式终端的版本管理器设置。Chromium 仍需安装在当前服务用户可以访问的位置。

```bash
systemctl --user daemon-reload
systemctl --user enable --now yingxu
systemctl --user status yingxu
journalctl --user -u yingxu -n 100 --no-pager
```

需要用户退出登录后继续运行，可由管理员为该用户启用 linger：

```bash
sudo loginctl enable-linger "$USER"
```

端口已由前台启动占用时，应先停止前台服务，再启动 systemd。不要让两个进程同时写同一个数据目录。

## 服务器私有访问

完整工作台目前没有登录系统和访问鉴权，包含工程编辑、模型调用与文件上传接口。服务器继续监听 `127.0.0.1`，通过 SSH 登录授权控制访问，无需将 8080 端口开放到公网。

在自己的电脑执行下列命令，把 `用户名@服务器地址` 替换为实际 SSH 账号和主机：

```bash
ssh -N -L 8080:127.0.0.1:8080 用户名@服务器地址
```

保持该连接，浏览器打开 `http://127.0.0.1:8080`。本机外部 AI 客户端也可使用 `http://127.0.0.1:8080/mcp`。这只是将本机连接转发到服务器，并未开放远程 MCP 公共端点。

若电脑上的 8080 已占用，可把隧道左侧端口改为 8081，浏览器与 AI 客户端随之使用 8081；服务器的 `RENDER_ORIGIN` 仍保持其实际监听地址 `http://127.0.0.1:8080`。

## 数据、备份与升级

`data` 中包含工程 JSON、`uploads` 原始素材、`exports` 成片、AI 和导出任务记录、加密设置与 `.settings.key`。`.settings.key` 用于解密模型设置，备份时必须连同隐藏文件一起保留。对外共享工程时，优先使用工作台的 ZIP 工程包，它只包含工程和被引用素材，不包含模型密钥。

升级前等待导出结束并停止服务，然后备份实际数据目录：

```bash
systemctl --user stop yingxu
mkdir -p "$HOME/yingxu-backups"
tar -czf "$HOME/yingxu-backups/data-$(date +%Y%m%d-%H%M%S).tar.gz" data
git pull --ff-only
npm ci
npx playwright install chromium
npm run build
go build -o bin/yingxu ./cmd/server
systemctl --user start yingxu
curl --fail http://127.0.0.1:8080/api/health
```

这些命令在仓库根目录执行，适用于使用上面的 systemd 单元且没有未提交源码修改的安装。使用自定义数据目录时，把备份命令中的 `data` 换成实际目录。正在运行的 AI 和导出任务在服务重启后会标记为中断，需要重新提交；已经保存的工程继续保留。

## 故障排查

| 现象 | 检查与处理 |
| --- | --- |
| 提示前端未构建 | 在仓库根目录运行 `npm ci`、`npm run build`，确认 `-dist` 指向正确目录 |
| 找不到 Chromium | 以服务用户运行 `npx playwright install chromium`，或检查 `CHROME_PATH`；缺系统库时安装 Playwright 依赖 |
| 预览或导出中文字变方块 | 安装中文字体，重新启动服务并重新生成预览或导出 |
| 找不到 Node / FFmpeg / FFprobe | 检查终端和 systemd 中的 `PATH`；确保运行用户可以执行这些程序 |
| 导出排队 | 当前导出采用后台队列，等待前面的任务完成，或取消不需要的任务；刷新页面后可恢复查看 |
| 导出长时间没有进展 | 查看任务中文错误与服务日志，检查素材是否缺失、浏览器能否启动、磁盘是否充足；异常停滞会超时失败，可修正后重试 |
| 域名访问无法导出 | 使用本机或 SSH 隧道地址；代理环境下把 `RENDER_ORIGIN` 设置为后端实际本机地址 |
| 本地配音不可用 | 安装 `espeak-ng` 并确认有 `cmn` 音色，必要时设置 `LOCAL_TTS_PATH` |
| 生图提示预期 JSON | 确认基础地址及版本前缀正确，检查供应商是否支持 `/images/generations`；网页或网关错误页不能当作 API 响应 |
| 模型列表为空或报错 | 供应商可能没有 `/models`；手动填写准确的模型名后继续配置 |
| AI 只回复文字 | 更换或正确配置支持标准工具调用的文本模型，普通对话成功不代表能剪辑 |
| MCP 返回拒绝或连接失败 | 确认使用本机 HTTP 地址、POST 协议及支持 HTTP MCP 的客户端；浏览器直接打开 `/mcp` 不能用于验收 |
| 模型设置无法解密 | 检查原数据目录中的 `.settings.key` 是否随备份恢复，不能用另一份密钥替换 |

更多使用步骤见 [使用指南](使用指南.md)，外部 AI 连接与接口约定见 [AI 接入说明](AI接入.md)。
